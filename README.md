# Система онлайн-записи в автосервис

Веб-кабинет сотрудника автосервиса для записи клиентов на обслуживание,
просмотра записей, причин отказов и уведомлений. Версия приложения: **0.0.5**.
Лабораторные работы по дисциплине МиСПИСИТ.

Стек: Python 3.13, Django 5.2.19, Django Templates, Bootstrap 5.3.9,
HTML/CSS, PostgreSQL 16, Django ORM.

## Запуск

```text
Репозиторий: https://github.com/yaganovvadimka-rgb/mispisit-labs
Ветка: lab5
Pull Request: [ВСТАВИТЬ ССЫЛКУ ПОСЛЕ СОЗДАНИЯ PR]
Образ: yaganovvadimkargb/mispisit-labs:0.0.5
```

Страница образа: [https://hub.docker.com/r/yaganovvadimkargb/mispisit-labs](https://hub.docker.com/r/yaganovvadimkargb/mispisit-labs)

Для запуска нужен Docker с поддержкой Docker Compose.

```sh
git clone -b lab5 https://github.com/yaganovvadimka-rgb/mispisit-labs
cd mispisit-labs
docker compose up -d
```

После запуска сайт открывается по адресу [http://localhost:8080](http://localhost:8080).
Структура базы создаётся автоматически миграциями Django. При первом запуске с новым
томом список записей, журнал отказов и уведомления пустые, демонстрационные записи не загружаются.
Справочники услуг и мастеров заполняются автоматически миграцией.
Новая таблица `notification` добавляется тем же встроенным механизмом Django,
который уже использовался в предыдущей работе. Новый инструмент миграций не подключается.
Для старых записей уведомления задним числом не создаются.

## Страницы

| Адрес | Что на странице |
| --- | --- |
| [http://localhost:8080/](http://localhost:8080/) | Главная кабинета сотрудника, версия приложения, количество записей и отказов, услуги и переходы к действиям |
| [http://localhost:8080/bookings/](http://localhost:8080/bookings/) | Список записей на обслуживание: клиент, автомобиль, услуга, мастер, дата, время и статус; до первой записи — пустое состояние с кнопкой создания записи |
| [http://localhost:8080/bookings/new/](http://localhost:8080/bookings/new/) | Форма записи: данные клиента и автомобиля, услуга, мастер, дата, время и комментарий |
| `http://localhost:8080/bookings/<id>/` | Карточка записи: данные клиента и автомобиля, услуга, мастер, время визита и статус; вместо `<id>` указывается номер записи |
| [http://localhost:8080/bookings/rejected/](http://localhost:8080/bookings/rejected/) | Причина отказа и журнал отклонённых попыток: кто, что пытался сделать и почему запись не создана; до первого отказа — пустой журнал |
| [http://localhost:8080/notifications/](http://localhost:8080/notifications/) | Уведомления сотруднику о новых записях: номер записи, клиент, автомобиль, услуга, мастер, время визита и статус прочтения |

Данные хранятся в PostgreSQL (сервис `db`, том `dbdata`). После `docker compose down`
и `docker compose up -d` записи сохраняются. Флаг `-v` у команды `docker compose down`
удаляет том вместе со всеми данными базы.

## Событие лабораторной работы 5

Выбран вариант «уведомление человеку». После успешного создания записи через
форму приложение сохраняет одно сообщение сотруднику в таблице `notification`.
Сообщение и запись сохраняются в одной транзакции. При отказе из-за неверной
формы, занятого времени или другого ограничения уведомление не создаётся.

Поля новой таблицы: `id`, `booking_id` (уникальная ссылка на запись), `message`
(текст с данными визита), `created_at`, `status` (`new` / `read`), `read_at`.
В сообщении сохраняются данные на момент события. Со страницы уведомлений
можно открыть карточку конкретной записи.

В меню всех страниц и на главной есть переход к уведомлениям. Рядом с пунктом
«Уведомления» показан жёлтый счётчик `+1`, `+2` и далее — количество непрочитанных.
При нулевом количестве он скрыт. То же число показано на главной и
в разделе уведомлений. Открытие страницы
не меняет статус: кнопка «Отметить прочитанным» отправляет POST-запрос с
CSRF-токеном. Статус становится «Прочитано», сохраняется время первого
прочтения. Повторный запрос не изменяет это время.

Отдельный экран наблюдения, worker, Mailpit и Prometheus в этой версии
не добавляются. Для реальной эксплуатации автосервису пригодятся SMS клиенту
с подтверждением и напоминанием о визите; в этой работе используется внутренний
канал, доступный в браузере сотрудника.

### Сценарий для скриншотов

1. Открыть «Уведомления» до первой записи в версии 0.0.5: видны пустое состояние
   и число непрочитанных 0. На уже заполненной базе ранее созданные уведомления
   остаются на странице.
2. Нажать «Создать запись» и оформить допустимый визит на свободное будущее время.
3. По ссылке из подтверждения открыть уведомление: видны введённые данные,
   номер записи, время создания и статус «Новое».
4. При необходимости нажать «Отметить прочитанным»: статус меняется, число
   непрочитанных уменьшается. Неверная запись по-прежнему открывает страницу отказа.

## Подготовка публикации

Публикация образа и создание Pull Request выполняются владельцем репозитория.
Для сборки и публикации нового тега под Intel используется команда:

```sh
docker buildx build --platform linux/amd64 -t yaganovvadimkargb/mispisit-labs:0.0.5 --push .
```

Сделайте образ публичным, создайте Pull Request из `lab5` в основную ветку и
замените метку ссылки в разделе «Запуск» и в отчёте на фактический URL.
Теги `0.0.1`–`0.0.4` не перезаписывайте; после слияния ветку `lab5` сохраните.
